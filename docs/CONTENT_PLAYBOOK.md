# 青年周刊 · 内容手册（Content Playbook）

> 目标：把周刊做成「有观点、有洞察、可行动」的杂志级内容，而不是链接聚合。
> 读者：内容主编与创作者。操作流程见 [PUBLISHING_RUNBOOK.md](./PUBLISHING_RUNBOOK.md)。

---

## 1. 内容价值观：每期回答读者三个问题

1. **为什么我要关心这件事？**（价值锚点）
2. **它对我有什么启发或帮助？**（洞察）
3. **我现在能做什么？**（行动）

> 判断标准：删掉这个条目后，读者会不会觉得「少了点什么」。
> 删了也无所谓，就是没有价值，不要写。

---

## 2. 每期结构（模板）

### Frontmatter（必须完整）

```yaml
issue: N
title: "青年周刊 · 第 N 期"
date: YYYY-MM-DD
published: true
cover: "./assets/cover.png"
description: "一句话说明本期主题，必须有吸引力，不超过 60 字"
```

### 正文结构（建议 300–500 行 Markdown）

```markdown
## 刊首语
（150–300 字：围绕一个主题展开，像朋友聊天，有观点、有温度，结尾抛出一个问题或邀请）

## <板块名>
### <条目标题>
（120–300 字/条：是什么 → 为什么重要/有趣 → 关键洞察或行动建议；禁止只贴链接）

（每个板块 2–4 个条目，每期 4–6 个板块）

## 本周行动清单
- [ ] 1 件本周就能做的事
- [ ] 1 件本周就能做的事
- [ ] 1 件本周就能做的事

## 本周金句
> 一句话，有力量，可引用。
```

### 板块池（9 个，每期选 4–6 个）

| 板块 | 内容 |
|------|------|
| 刊首语 | 主编视角，本期主题定调 |
| 科技新势力 | AI / 工具 / 编程 / 硬件 |
| 二次元次元壁 | ACG / 漫展 / 动画 |
| 游戏研究所 | 游戏评测 / 攻略 / 行业 |
| 青春故事会 | 成长 / 职场 / 学习 / 心理 |
| 好工具 | 效率工具 / 生活助手 / 开发利器 |
| 在看什么 | 影视 / 书籍 / 播客 |
| 一周图鉴 | 视觉 / 摄影 / 设计 / 艺术 |
| 谁在招人 | 招聘 / 实习 / 机会 |

（另设「编读往来」板块用于读者反馈与话题讨论，视内容弹性加入。）

## 3. 写作规范

1. **禁止**：纯链接罗列、百科式简介、空洞套话（「赋能」「抓住风口」「不可错过」）。
2. **必须**：每个条目给出「具体事实 / 数据 / 案例 / 操作步骤」中的至少 2 种。
3. **标题要有信息量**：如「Cursor 0.50 实测：这 3 个新功能让重构快了 1 倍」，而不是「Cursor 发布新版本」。
4. **行动导向**：每条尽量给一个「你现在就能做」的动作。
5. **中文写作**：简体中文，口语化但有信息密度，像给聪明朋友写的周刊。
6. **Markdown 规范**：`##` 用于板块，`###` 用于条目；正文不用 `h1`；引用用 `>`；列表用 `-`。
7. **链接**：可保留 1–2 个高质量链接（官方 / GitHub / 深度文章），但不要每条都只有链接。
8. **图片**：不新增不存在的图片引用；需要图时只用 `./assets/cover.png` 或本期 `assets/` 目录里已存在的文件。
9. **日期与期号**：保持各期原 date 不变（历史期次时间线）；不写明显穿越的「未来事件」。

---

## 4. 质量关卡（主编审校标准）

- [ ] frontmatter 合法（YAML 可解析，title/date/published/cover/description 齐全）
- [ ] 每期至少 4 个板块 + 1 篇刊首语 + 行动清单 + 金句
- [ ] 每个条目有「价值锚点 + 洞察 + 行动」至少两项
- [ ] 无纯链接条目、无空洞套话
- [ ] Markdown 结构正确（`##`/`###`/列表/引用）
- [ ] 长度达标（每期正文 250 行以上为佳）
- [ ] `youth-weekly validate` 通过（frontmatter + 资产引用自动校验）
- [ ] `update_readme.py --check` 通过（README 索引一致）

---

## 5. 分工建议

- 内容主编：制定选题方向、抽查审校、最后统一润色刊首语。
- 创作者 A：第 001–004 期
- 创作者 B：第 005–008 期
- 创作者 C：第 009–013 期

---

## 6. AI 辅助生产（提示）

- 可用 LLM 辅助：初稿改写、标题打磨、刊首语起稿、条目信息量检查。
- 但最终稿必须经过人工判断：AI 初稿往往「正确但平庸」，主编负责注入观点与温度。
- 任何 AI 生成的图片/文字引用，需确保本期 `assets/` 中确有对应文件（见 §3-8）。
