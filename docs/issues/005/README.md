## 刊首语

今天是五四青年节，也是《青年周刊》第五期。想借这个日子聊一件看起来毫不相关的事：GitHub 上线二十年了。

二十年前，几个年轻人用 Ruby 写了一个网站，最初只想解决"两个人怎么一起改代码"这种琐碎问题。如今它是全球最大的开源社区，托管着上亿个仓库，也托起了无数年轻人的第一份作品、第一份 offer、第一次被陌生人说"谢谢，这个项目帮了我"。

开源精神的内核，和青年精神其实是同一种东西：

- 不等人许可，先动手；
- 不迷信权威，先验证；
- 做出来的东西，愿意分享出去。

所以这一期我们不只纪念 GitHub，更想借它讲清一件事——在 AI 已经能帮我们写代码的时代，"亲手 build、freely share"依然是年轻人最稀缺的能力。

你人生中第一个让陌生人受益的产出是什么？欢迎在评论区告诉我。

## 科技新势力

### GitHub 20 年：从解决一个小麻烦，到改变一个行业

2006 年 GitHub 上线，2008 年开放注册，2018 年以 75 亿美元被微软收购，到 2026 年 AI 已经深度嵌入它的每一条工作流。

回头看，GitHub 真正的发明不是"存代码"，而是 PR、Issue、fork 这套协作语言。它把"给一个陌生项目做贡献"的门槛降到了最低：

- fork 一下，仓库就变成你自己的副本；
- 改几行，不打扰任何人；
- 提个 PR，你就成了一个开源项目的贡献者。

这件事对年轻人最有价值的启示是：**影响力不是等来的，是"提交"出来的。** 别总想着"等我厉害了再参与"。

现在就做：打开一个你天天在用的开源项目，找标着 good first issue 的任务，提你的第一个 PR。

### 四款 AI 编程助手实测：别再吵"谁最强"，先想清楚你要什么

Copilot、Cursor、Claude Code、通义灵码各有各的脾气，真用起来差别很大：

- **Cursor** 的 Agent 模式适合从零搭原型，一句话就能生成整个目录结构，但大项目里偶尔会自作主张。
- **Claude Code** 强在啃大型仓库、重构和读遗留代码，适合后端与架构向的活。
- **Copilot** 胜在零门槛和生态，开着就不太想关，但深度任务需要你更会写 prompt。
- **通义灵码** 对中文注释、国内框架和合规场景最友好，适合学生党和国内团队。

我的判断是：**别为"最强"付费，为"你最常干的活"付费。**

现在就做：拿一个真实小项目，在两家上各跑一遍，记录谁更省心，再决定留哪家。

### GitHub 被忽略的免费能力：浏览器里就能跑环境

Copilot Workspace 正式版、GitHub Models 内置开源模型、Codespaces 启动提速 50%——这三个功能凑在一起，对"没有高配电脑、没有预算买 API"的学生党是实打实的福利。

你不再需要先装好 Node、Python、数据库，才能跑一个别人的项目：

- 浏览器打开 Codespaces，环境已经替你配好；
- GitHub Models 让你不用花钱就能调用开源大模型；
- Copilot Workspace 能把一个 issue 直接推进到可运行的改动。

这套逻辑值得注意：**开发的门槛正在从"会不会"变成"愿不愿意开始"。**

现在就做：用免费额度在浏览器里启动一个感兴趣的仓库，跑起来再说。

### 二十年里的那一句"Code is how we build"

GitHub 有一句流传很广的话：*"GitHub is how people build software."* 二十年过去，这句话的前半段正在被 AI 改写——人不再需要亲手敲每一行代码，但"build"这件事反而变得更值钱：能把想法拆成步骤、能把 AI 的产出判断好坏、能把一个粗糙 demo 打磨成别人愿意用的东西，这些能力 AI 还替代不了。

所以别把"AI 会写代码了"理解成"程序员没用了"，它真正的意思是：**写代码变便宜了，但判断、拆解和交付变贵了。** 想清楚这个，就知道该往哪使劲。

## 游戏研究所

### 五月游戏大作前瞻：攒钱之前，先想清楚哪款真适合你

《黑神话：悟空》定档 8 月 20 日，《艾尔登法环》DLC 六月发售，《空洞骑士：丝之歌》和《怪物猎人：荒野》也在路上。大作扎堆是好事，但对成年人来说，真正稀缺的不是游戏，是**整块的可支配时间**。

一款 80 小时的开放世界，意味着接下来三个月每个周末都要"投资"进去。所以别按热度买，按"你一周能稳定拿出多少小时"来排：

- 一周能拿出 15 小时以上，3A 大作随便挑；
- 只有 5 小时左右，选流程短、随时能停的作品更值；
- 纯碎片时间，不如玩几局能快速收场的独立游戏。

游戏是消费品，不是 KPI。买最适合你节奏的那款，才是对钱包和心情双重负责。

### 《艾尔登法环》DLC 备战：与其刷到 200 级，不如练熟三件事

攻略帖总爱教你"升到 200 级、收集强力战灰、备份存档"，这些都对，但真正的备战核心不是数值，是**手感**。等级能刷，肌肉记忆刷不出来。

DLC 开荒前，我建议做三件更实在的事：

- 用现有存档把主力武器各打一遍，确认自己最顺手的那套；
- 把常用祷告、战灰的出手节奏重新过一遍；
- 至少备份一次存档——这不是怕死，是尊重你已经投入的几百小时。

数值可以补，手感只能练。与其把 DLC 前的时间都花在刷级上，不如让自己回到"肌肉比大脑先反应"的状态。

### 手游速递：与其追版本，不如守住一个"主线"

本周《原神》4.8 夏日活动与纳塔预热、《崩坏：星穹铁道》2.3 匹诺康尼尾声、《绝区零》1.3 大型更新扎堆更新。手游最擅长的就是**用不断更新的活动制造"错过焦虑"**，让你每天上线打卡，最后变成游戏在玩你。

我的建议很朴素：

- 挑一款游戏当"主线"，其他一律只做"零氪浅尝"；
- 每天固定的 20 分钟留给那款你真正喜欢的；
- 剩下的更新，用"这期内容我错得起"的心态跳过。

把选择权拿回来，游戏才会重新变成放松，而不是任务。

## 青春故事会

### 五四青年说：青年不是年龄，是一种"还没认命"的状态

李大钊说"青年不是年龄，是心态"，这话到今天依然成立。我见过二十岁就"认命"的人，也见过四十岁还在折腾新方向的人。

所谓青年精神，拆开就是四件事：

- **好奇心**：对世界保持"这为什么是这样"的追问；
- **勇气**：敢于尝试，也敢于搞砸；
- **热情**：对热爱的事全力以赴，不计较即时回报；
- **责任**：在没有人要求的情况下，主动把一件事负责到底。

其中最难得的是最后一件。判断自己是不是还"年轻"，有个简单的测试：这周有没有一件你主动揽下来、而不是被分配的活？

现在就做：认领一件团队里没人愿意碰的小事，做完用一句话写下复盘。

### 技术面试的真相：STAR 法则救不了没有积累的人

面试官问"说说你最有成就感的项目"，STAR 法则能帮你不慌，但它只是表达框架，救不了空洞的内容。面试真正想判断的只有一件事：**你能不能稳定地把想法变成结果。**

所以准备面试的正确顺序是反过来的：先攒"结果"，再练"表达"。具体做法是把最近三个项目各写一张 STAR 卡片：

- **情境（Situation）**：当时面对什么问题；
- **任务（Task）**：你负责哪一部分；
- **行动（Action）**：你具体做了什么、为什么这么做；
- **结果（Result）**：量化成果，比如"性能提升 40%""首屏耗时降低一半"。

"性能提升 40%"比"优化了性能"有力十倍。写不出来，说明这个项目你还没吃透，这正是下一步该补的地方。

### 普通本科如何拿到大厂 offer：把"运气"拆成可复制的过程

常有人说"拿 offer 靠运气"，但运气背后是有结构的。一位普通本科、三年经验后拿到大厂 offer 的读者复盘过他的路径：

- 系统复习基础：操作系统、网络、数据结构，打好地基；
- 刷 200+ 道高频题，训练的是解题的套路和手感；
- 把自己负责的项目吃透，挖掘每一个可讲的亮点。

他最重要的经验只有一条：**把"不会"当成交谈，而不是当众出丑。** 面试时不会的题可以直接说不会，再讲你的思路，因为面试官看的是思考过程，不是标准答案。机会留给有准备的人，但"准备"是指可复用的方法，不是刷完所有题。

## 好工具

### GitHub CLI 实战：让提 PR 像发消息一样快

`gh` 是 GitHub 官方的命令行工具，能把你最重复的三件事压成一条命令：

```bash
# 克隆并直接进入目录
gh repo clone owner/repo && cd repo

# 提 PR，标题和正文一次到位
gh pr create --title "feat: 新功能" --body "描述"

# 看自己名下所有 PR 的状态
gh pr status
```

配合 Actions 缓存依赖，CI 还能再快一截。这里的核心不是省几秒，而是**把重复操作交给工具，把判断留给自己**——省下来的注意力，才是真正的生产力。

现在就做：`gh auth login` 走一遍，把日常的建 PR 流程换成一条命令。

### 终端别名：省下的每一次敲击，都是注意力

真正高效的终端，不是装最多的插件，而是把你每天重复十次的命令压成两三个字母：

```bash
alias gs='git status'
alias gc='git commit'
alias gp='git push'
```

小技巧的关键在于：**别名要少而精，够你肌肉记忆。** 别一次配置五十条，最后一条都想不起来。

现在就做：先列出一周里你最常敲的三条命令，把它们缩成别名，用熟之后再继续加。

### Copilot 的 prompt 工程：把注释写成需求，而不是祈祷

很多人抱怨 AI 补全"不准"，其实是没把需求说清楚。同样要一个防抖函数，"写个防抖"和"生成一个 300ms 防抖、支持取消、用 TypeScript 箭头函数写的纯函数"是完全不同的结果。

把 prompt 当需求文档写，三个要素缺一不可：

- **做什么**：功能本身，说清边界；
- **约束**：延迟多久、支不支持取消、用什么语言和风格；
- **验收标准**：生成的代码要满足什么才算合格。

再配合 `/explain` 讲代码、`/test` 生成测试、`/refactor` 重构，AI 就从"补全"升级成"结对"。重要代码照旧要 review——AI 是副驾驶，方向盘还得在你手里。

## 在看什么

### 书：《代码大全》——被书名耽误的工程学教科书

Steve McConnell 的《代码大全》快三十年历史了，依然值得推荐。它讲的不是语法，而是软件构建这件事本身：

- 怎么写才可读；
- 怎么测才有效；
- 什么时候该重构。

书名听着像"大全"式的百科，其实是本**讲工程判断的书**。适合写过一两年代码、开始关心"我写的代码别人能不能维护"的人。初学太深，资深会觉得是总结，中间那一段刚刚好。

### 播客：《内核崩溃》——系统编程的冷门魅力

一档关于操作系统和系统编程的播客，聊 Linux 内核怎么工作、为什么 C 语言还没被淘汰、从零写一个操作系统是什么体验。

这类内容的价值不在"学会内核"，而在**把你对计算机的理解往下推一层**：当你知道栈、调度、内存这些概念怎么运转，写上层代码时会少很多想当然。想补系统知识又啃不动大部头教材的人，可以从这里入门。

### 剧集：《人生复本》——每个选择都在分裂出另一个你

科幻悬疑剧《人生复本》讲的是平行世界：主角每一次重大选择，都会分裂出一个走了另一条路的自己。

它表面是悬疑，内核是**关于"选择与代价"的哲学**——我们总幻想"如果当初"，却忘了每个选择背后都有它要付的账。适合喜欢烧脑、又不只想看爽片的观众。

看完不妨问自己一个问题：如果今天的你是某个平行世界里的"另一个版本"，你会羡慕他还是庆幸？

## 谁在招人

### 本周技术岗位精选：精准匹配胜过海投二十家

本周有三类机会值得关注：

- 字节跳动 AI 算法工程师（大模型训练/推理优化，北京/上海）；
- 蚂蚁集团前端技术专家（互动图形引擎，杭州）；
- 腾讯 AI 产品实习（深圳，在校生可投）。

给正在投递的人一个建议：**与其海投二十家，不如挑一家，对着 JD 逐条改简历里的"项目关键词"。** 比如岗位要 WebGL，你就把"做过 Canvas 可视化"展开写清用了什么、解决了什么、效果如何。精准匹配的一封，胜过泛泛而投的二十封。

### 实习岗位：在校生最该投的是"能写进简历的项目"

腾讯 AI 产品实习这类岗位，对在校生来说门槛不算高，真正拉开差距的是"你是否带着作品来"。

与其焦虑学历背景，不如在投递前准备一个**能当场演示的小作品**：一个分析你感兴趣数据的脚本、一个解决你身边小问题的网页，都比简历上的"熟悉 xxx"更有说服力。

记住：实习最大的价值不是工资，是**给你一个"真实项目 + 可复述成果"的素材**，让你的下一份简历有东西可写。
