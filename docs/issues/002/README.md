## 刊首语

这周科技圈最大的新闻是 GPT-5 发布：多模态更强、推理更快、上下文更长。朋友圈刷屏的瞬间，我看到两种人——一种立刻去排队试用，另一种在问「这对我到底意味着什么」。

我想站第二种人这边。一个新模型的发布，和「你能不能因此把事情做得更好」之间，隔着一段很长的路。真正拉开差距的，从来不是谁先用了新工具，而是谁把工具用进了自己的日常流程。

所以本期我们不讲「GPT-5 有多强」的复读，而是聊几件更实在的事：新模型到底改变了什么、4 月新番该怎么挑、想开发第一款独立游戏该从哪里迈出第一步，以及怎么把已经拥有的工具用到 80%。

本期我们也会把这条原则用在自己身上：每一个推荐，都附上了一个「你现在就能做」的动作。

看完之后，不妨问自己：你手头最常用的那个工具，你真的把它用到 80% 了吗？

——《青年周刊》编辑部

## 科技新势力

> 不追热点，只追「这件事对我有没有用」。

### GPT-5 发布：先别急着追新，先问它解决你什么问题

GPT-5 的核心升级是多模态实时理解、更快推理和超长上下文，还能原生跑代码。

但「更强」不等于「你更需要」。判断一个工具值不值得跟进，标准只有一条：它能不能解决你现在真实存在的问题。如果它只是让你的 demo 更炫，却带不进你的工作流，那它对你来说就是个玩具。

三个值得关注的实际变化：

- 能实时读视频流，意味着「看懂现场」类应用（监控、质检、直播辅助）会加速落地；
- 上下文变长，意味着「读一整个代码库再回答」变得更可行；
- 原生代码执行，意味着 AI 从「给建议」走向「交付结果」。

行动建议：别急着升级付费套餐。先用你手头最熟悉的项目，丢一个真实任务给它，看它能不能比你现在的工具做得更好，再决定。

### 把提交信息写清楚，是最便宜的团队投资

「feat: 加登录」「fix: 修了个 bug」这种提交信息，半年后回看就是一堆谜语。

Conventional Commits 只要求一个动作：用 `feat / fix / docs / refactor / test / chore` 这样的前缀，把「做了什么」说清楚。配合 `commitlint` 和 `commitizen`，可以自动检查、交互式生成。

为什么值得做：好的提交历史是给「三个月后的自己」看的。你今天的 30 秒，能省下未来同事（或未来的你）半小时的考古时间。

行动建议：这周开始，把每一次提交都写成「动词 + 对象 + 原因」，哪怕只是个人项目。

### VS Code 的 AI 结对编程：从「补全」到「对话」

微软把 Copilot 从补全推进到了结对：Copilot Chat 能解释代码、生成测试，Copilot Workspace 能用自然语言生成项目结构。

它和 Cursor 的区别在于：Copilot 更像「嵌在你熟悉环境里的同事」，Cursor 更像「围绕 AI 重新设计的编辑器」。选哪个，取决于你更想保留哪种工作习惯。

行动建议：无论用哪个，都试一个固定用法——让 AI 先解释一段你看不懂的遗留代码，再让它写测试。解释 + 验证，比让它直接写新代码更能学到东西。

### 让终端更聪明的三个别名

把高频命令压成别名，是成本最低的「效率升级」：

- `alias gs='git status'`：最常用的查看动作，两个字搞定；
- `alias gl='git log --oneline --graph'`：一眼看清分支走向；
- `alias ..='cd ..'`：少敲两个字符，一年下来能省不少时间。

行动建议：把你最近一周重复敲过 10 次以上的命令，各写成一个别名，写进 shell 配置里。

## 二次元次元壁

> 这季新番很多，但你要的只是「今晚想被什么情绪击中」。

### 4月新番导视：别按「霸榜」选番，按「你要什么」选

这季新番多到挑花眼。与其照搬排行榜，不如先问自己这个季度想要什么：

- 想要被治愈 → 《迷宫饭》完结篇，美食与冒险的温柔收官；
- 想要悬疑烧脑 → 《我推的孩子》第二季，光鲜背后的账本继续翻；
- 想要热血爽快 → 《胆大党》，骰子决定命运的荒诞战斗；
- 想要情怀 → 《夏日大作战2》，原班人马回归。

排行榜告诉你「大家都在看什么」，但你缺的是「我今晚想被什么情绪击中」。后者只有你自己知道。

### 《迷宫饭》完结：生存哲学藏在菜谱里

历时两年的《迷宫饭》迎来完结。表面是「在地下城做饭」的脑洞，内核是一道道关于生存与道德的判断题：在资源匮乏时，吃什么、不吃什么，都是选择。

它的高级之处在于，从不把「吃魔物」当猎奇，而是认认真真讨论成本、营养与伦理。这种「用具体细节讲宏大主题」的功力，是很多作品学不来的。

行动建议：看完之后，不妨用它的思路重看自己手头的一个「资源困境」——你真正可用的选项，比你以为的多吗？

### 《夏日大作战2》：情怀可以重来，但要有新东西

原班人马回归的《夏日大作战2》，最危险的地方恰恰是「情怀」。续作很容易变成「把第一部的名场面再演一遍」。

判断一部续作值不值得看，我只看一点：它有没有提出一个第一季回答不了的新问题。有，就是成长；没有，就是怀旧消费。

行动建议：看续作之前，先花 5 分钟回想你记住的是「哪个画面」还是「哪个问题」，这决定了你是去看故事，还是去被提醒「当年看过」。

## 游戏研究所

> 想做出自己的游戏？先把「完成」这件事练会。

### 独立游戏开发第一课：先做出一个能玩的「最小游戏」

想开发游戏的人，最容易死在第一步：目标定成「我要做一款开放世界」。

正确的路径是反过来：先做一个 10 分钟就能玩的完整小游戏（贪吃蛇、俄罗斯方块、打砖块），把「立项—开发—完成—发布」整个循环走一遍。引擎选 Godot（上手平缓、免费）或 Unity（生态成熟）都行。

为什么最小游戏重要：它让你第一次尝到「做完」的滋味。完成感是坚持下去的燃料，而「永远在开发中的大作」只会耗尽热情。

行动建议：本周末花 3 小时，跟着一个官方教程做出第一款能玩的小游戏，哪怕只有一关。

### 《哈迪斯2》正式版：把「死亡」设计成奖励

《哈迪斯2》正式版本月发布，新增完整剧情、新角色墨利诺墨和塔纳托斯试炼。

它最值得学的一课是：把玩家最讨厌的事（反复死亡）做成了核心乐趣——每次死亡都带回新对话、新能力、新剧情。这个设计思路可以迁移到任何「需要用户重复」的产品里：让每一次重复都带走一点增量。

行动建议：如果你在做一个需要用户反复使用的功能，问一句：用户这次回来，比上次多了什么？

### 《原神》4.6：水下世界不是「内容」，是「理由」

4.6 版本开放枫丹水下世界，加入新角色那维莱特与大型支线「旧日之海」。

一个观察：真正留住玩家的不是新地图有多大，而是「有没有一个想让我回去的理由」。新剧情、新角色、新机制，本质都是在制造这个理由。

行动建议：判断自己要不要回坑，别问「更新了什么」，问「我上次离开时想解决的问题，这次被解决了吗」。

### Steam 新品节：用 demo 决定，别用预告片决定

新品节最划算的地方是：大量未发售游戏放出免费 demo，你可以亲手试玩，而不是看预告片脑补。

一个筛选策略：每个 demo 只给 15 分钟。15 分钟内没让你产生「想继续玩」的冲动，就果断跳过。你的时间比「把每个 demo 都打完」值钱得多。

行动建议：这周挑 3 个感兴趣的 demo，各玩 15 分钟，记下哪个让你停不下来。

## 青春故事会

> 学习与工作，都有更省力的打开方式。

### 费曼学习法：把「看懂」变成「讲得出」

判断你有没有真的学会，只有一个标准：能不能用大白话把它讲给一个外行听。

费曼学习法只有四步：选一个概念 → 用简单的话解释 → 找出解释里的漏洞 → 回头简化。难就难在第二步——一旦你要「讲出来」，所有含糊的地方都会现形。

实践建议：每天学 1 小时、连续七天，胜过周末突击 7 小时；笔记用自己的话写，而不是抄书；最好的复习，是教会另一个人。

行动建议：这周学到的任何一个小知识，当天晚上用三句话讲给朋友或写下来。讲不出来的地方，就是你没学会的地方。

### 远程工作的隐形技巧：给时间建立边界

远程工作一年后，我发现最大的敌人不是效率，而是「工作和生活混在一起」。

三个立竿见影的调整：

- 环境上：哪怕只是书桌一角，也要有独立的「工作区」，坐下就是上班，离开就是下班；
- 节奏上：番茄钟 25+5 比「一口气干三小时」更可持续，设一个「下班仪式」（出门散步或收走工作设备）；
- 沟通上：文字说不清的立刻转语音或视频，重要决策落到书面，进度主动同步而不是等别人问。

远程不是「在哪都能干活」，而是「你必须更主动地管理自己的注意力」。

### 读者投稿：转行的难点不在技术，在思维

一位从土木转前端的读者分享：「最大的困难不是学技术，而是改变思维方式。工程思维是按图施工，编程思维是自己设计图纸。」

他还给了一条很实在的建议：不要裸辞转行，边工作边学习。经济压力会严重影响学习效率，而学习是需要冗余和松弛感的。

行动建议：如果你也在考虑转行，先别辞职，用业余时间做一个能放进作品集的小项目，用它来验证「我是真的喜欢，还是只是讨厌现在的工作」。

### 给拖延者的两个物理开关

拖延往往不是意志力问题，而是「启动成本太高」。两个物理层面的解法：

- 两分钟法则：任何两分钟能做完的事，立刻做掉，别放进待办清单；
- 环境开关：想读书，就把书放在枕头边而不是书架顶；想戒手机，就把它放到另一个房间充电。

核心思路是：别跟意志力较劲，去降低「开始」的门槛。门槛低了，行动就自然发生了。

## 好工具

> 工具不是越多越好，是「顺手」最好。

### Zed：为「快」而生的新编辑器

Atom 创始人团队用 Rust 重写的编辑器 Zed，主打 GPU 加速渲染和极低延迟，内置 AI 协作，还支持 Vim 模式。

它适合谁：写 Rust、Go、TS 等语言的开发者，尤其是受不了大编辑器启动速度和卡顿的人。但生态还在早期，插件不如 VS Code 丰富。

行动建议：别指望它一夜替代主力编辑器。用它开一个「第二编辑器」，处理轻量、快速迭代的小任务，用一段时间再判断。

### Obsidian 五个值得装的插件

Obsidian 的本地 Markdown 加双向链接是基本盘，真正拉开差距的是插件。

五个实用插件：

- Dataview：把笔记变成可查询的数据库，自动汇总带标签的条目；
- Templater：高级模板，新建笔记自动套用结构；
- Kanban：拖拽式看板，管理写作或项目进度；
- Excalidraw：手绘图表，适合画架构和思路；
- Mind Map：把大纲一键变思维导图。

行动建议：这周只装一个（推荐 Dataview），把一个「每天都要手动整理」的场景自动化掉，别贪多。

### Raycast 进阶：别只当它是个启动器

Raycast 的价值远不止「快速打开 App」：

- 剪贴板历史：`Alt + V` 调出，找回刚才复制过的东西；
- 代码片段：常用代码一键插入；
- 窗口管理：分屏、置顶不用再拖来拖去；
- 脚本扩展：支持 Python，把重复操作包成命令。

行动建议：找出你每天重复最多的一个动作（比如「打开某三个 App」），用 Raycast 把它做成一条命令，然后感受一下「少切换」的爽。

## 在看什么

> 轻松一点的推荐，也带一点「为什么要看」。

### 电影：《功夫熊猫4》：别期待超越，只期待开心

《功夫熊猫4》是标准的合家欢动画：故事轻快、动作精彩、彩蛋满满。它没想成为什么伟大的作品，只想让你笑着看完 90 分钟。

这也是一种能力——清楚自己要什么、并把它做到位，比什么都想做更难得。周末想放松，它就是正确答案。

### 书籍：《跨越鸿沟》：为什么好产品也会死

Geoffrey Moore 的经典判断：技术产品从「早期采用者」跨到「主流大众」之间，横着一条巨大的鸿沟，多数产品都死在这条沟里。

对个人的启发是：好想法和好结果之间也有一条鸿沟，叫「别人为什么要买单」。你做得再漂亮，如果没想清楚「谁会在什么场景下用它」，就还停在沟的这一边。

### 播客：《三五环》：把「转行」这件事聊透

《三五环》聊互联网产品、创业与生活，几期关于「设计师转产品」「远程工作五年」的单集尤其实在。

播客的正确用法不是「听完就算」，而是挑一集和自己处境相关的内容，边听边记下 3 个能用的动作。
